# Administrator access

The administrator console is not linked from public navigation. It uses an existing regular Auth.js account, a server-side `GraceAdministrator` membership, and a second-factor TOTP challenge. Proofs expire after ten minutes and are bound to the authenticated session and membership version. Each administrator API checks role and proof independently; mutations require same-origin requests. TOTP counters prevent reuse. Administrative actions record attempts and successes without provider credentials.

The first owner must be provisioned on a trusted host after the versioned migrations have run. Create a regular account through the application and obtain its user ID from a trusted database operator. Configure `POSTGRES_URL`, `AUTH_SECRET`, `GRACE_ENCRYPTION_KEY` (a separate 32-byte base64-encoded key), and `GRACE_CATALOG_ENABLED=1` on the appropriate server. Supply a randomly generated base32 TOTP secret through `GRACE_ADMIN_TOTP_SECRET` to `corepack pnpm admin provision <user-id>` using a secret-aware process environment. Never pass the TOTP secret in command arguments, record it in shell history, or log it. Enroll the same secret in the owner's authenticator. Bootstrap is limited to the first owner and does not reset existing administrators.

Owners can assign or disable other administrators in the Users section. Roles: viewers can view the dashboard, users, and audit log; operators can additionally manage provider keys and models; owners can also delete keys and manage administrator membership. Disabling or updating a membership invalidates that user's administrator proof. Recovery requires an authorized database operator; there is no authentication bypass.

New provider keys and models are disabled by default. Add a key, discover or manually register a model, run verification (a real inference call that may incur charges), explicitly permit the key/model association, and enable both the key and model. Only then can the existing shared-catalog chat path select it. Cloudflare requires its account ID and API token. Generic OpenAI-compatible providers additionally require exact hostnames in the server-side `GRACE_CUSTOM_PROVIDER_HOSTS` comma-separated allowlist. Generic providers allow only HTTPS, reject redirects and reject DNS resolutions containing non-public addresses. Lower key priority numbers are selected first. Discovery and verification status do not guarantee future uptime. For shared text-only models, a transient HTTP 429 or 5xx before the upstream stream is opened can retry another verified, permitted key for the same model, bounded to three candidates. It never retries after the stream opens, on authentication errors, or when tools are present. Administrators can define automatic routes containing explicitly interchangeable models across providers; the same pre-stream limit applies. Route-member priority selects the first eligible model, then candidates are interleaved to include other models before extra keys.

`GraceAdministrator` and `GraceAdminAudit` use deny-by-default RLS; application database connections must use a trusted server-only role. This interface does not include a CAPTCHA and is not a substitute for an independent security review. Never expose the database or encryption key to browser code.
