# Administrator operations

The console at `/administrator` is deliberately absent from public navigation. It uses a regular Auth.js account, server-side membership, TOTP MFA, and a production Turnstile challenge. Administrator proofs expire after ten minutes and are bound to the authenticated session and membership version. Each API independently checks role and proof, mutations require the same origin, and TOTP counters prevent reuse.

## Prepare production

1. Apply and verify all additive migrations and the database role/RLS assumptions described in [release and recovery](release-and-recovery.md). Preserve existing users and both migration histories.
2. In Vercel's project settings, configure `POSTGRES_URL`, a random independent `AUTH_SECRET`, `AUTH_URL` with the public HTTPS origin, `GRACE_ENCRYPTION_KEY` (a separate base64-encoded 32-byte random key), and `GRACE_CATALOG_ENABLED=1`. For initial setup, `/operator-key-generator.html` can create a canonical 32-byte base64 key locally in a trusted browser without sending or storing it; alternatively use an offline cryptographic generator. Back up the encryption key securely: losing it prevents decryption of provider credentials and TOTP seeds. Never replace an in-use key without migrating the encrypted data, and never reuse `AUTH_SECRET` as the encryption key. For serverless deployments, prefer Supabase's IPv4-compatible **transaction pooler** connection string; the direct database endpoint can be IPv6-only. If a direct Supabase URL is already stored as a sensitive variable, the optional `GRACE_SUPABASE_POOLER_HOST` can instead specify the project's exact AWS pooler hostname. The server derives a port 6543 transaction-pooler URL without exposing or copying the password and restricts the destination to Supabase's pooler domain. Supabase pooler connections validate the hostname and certificate using the bundled public Supabase Root 2021 CA. Prepared statements and pipelining are disabled in transaction mode; Drizzle Kit uses session mode for schema tooling.
3. Configure a Cloudflare Turnstile site for the production hostname and set `NEXT_PUBLIC_GRACE_TURNSTILE_SITE_KEY` and server-only `GRACE_TURNSTILE_SECRET`. Registration and administrator setup/MFA fail closed if these are missing or verification fails.
4. Set a temporary, cryptographically random `GRACE_BOOTSTRAP_SECRET` of at least 32 characters in the production environment. For example, generate it privately with `openssl rand -base64 32`. Do not paste any secret into an issue, chat, shell history, or source control.
5. Deploy with these settings, register and sign in to the account that should become owner, then visit `/administrator/setup`. Generate an authenticator key, enroll it as a time-based account, and provide its six-digit code and the bootstrap secret. Setup is serialized, requires an enabled regular account, and cannot run if any owner already exists, even a disabled one. Remove `GRACE_BOOTSTRAP_SECRET` from Vercel after the owner is created. Wait for a new TOTP code before signing in to `/administrator`; the enrollment code cannot be reused.

Alternatively, a trusted database operator may use `corepack pnpm admin provision <user-id>` with `POSTGRES_URL`, `GRACE_ENCRYPTION_KEY`, and a random base32 `GRACE_ADMIN_TOTP_SECRET` supplied through a secret-aware environment. Enroll the same key in the owner's authenticator. Do not put secrets in command arguments. The CLI and web setup share the same first-owner lock and do not reset existing owners.

Owners can assign and disable other administrator memberships in Users; membership changes invalidate existing administrator proofs. Viewers can read the dashboard; operators can additionally manage provider keys and models; owners can manage administrator membership, account policies, destructive catalog operations, and system settings. Recovery requires an authorized database operator; there is no authentication bypass.

## Provider catalog and routes

New provider keys and models are disabled by default. Add a real key, discover or manually register a model, run verification (a real inference call that may incur charges), permit the key/model association, and enable both key and model. Credentials remain server-side and are encrypted per row. Cloudflare requires an account ID and API token. Generic OpenAI-compatible providers additionally require exact hostnames in `GRACE_CUSTOM_PROVIDER_HOSTS`; only HTTPS and public DNS addresses are allowed, and redirects are rejected. Do not expose credentials in logs or screenshots.

For shared models, lower key priority numbers are tried first. Owners/operators may define routes containing **explicitly interchangeable** models and choose manual, fastest, reliable, or balanced ranking based on observed connection-opening signals. Up to three permitted candidates can be attempted before a stream opens for retryable authentication, rate-limit, network, timeout, or upstream failures. Invalid requests, tool use, caller cancellation, and streams that have already opened do not fall back. Failed credentials cool down for five minutes; temporary failures cool down for 30 seconds. Health reflects connection opening, not response completion; successful verification does not guarantee future uptime.

Mark a model as vision-capable only after confirming that its upstream supports the submitted image formats. Every eligible fallback for an automatic route must support vision before that route accepts images. Text attachments are included as text. Completed calls record the provider and upstream model that actually opened the stream; missing token reports remain unknown.

## Account policies, quotas and access

Owners can enable or disable non-administrator accounts and set hourly request quotas. PostgreSQL atomically reserves quota after request, model, tool, and attachment validation; attempts that reach generation count whether or not generation finishes, including tool continuations. The counter resets an hour after the first reservation. Existing network rate limits still apply. Active administrators cannot be disabled through account policy.

Owners can assign `free` or `custom` manually, optionally with an expiration time. An expired grant falls back to free using the database clock; active administrators receive custom access. Models and automatic routes can require custom access. Entitlements are enforced by the server both in model listings and at request time; a free route cannot expose custom-only members. **There is no payment processing, automated billing, or paid subscription lifecycle.**

## Attachments, announcements and emergency controls

JPEG/PNG images and UTF-8 text files are stored privately in PostgreSQL, limited to 2 MiB per image or 32 KiB per text file and 20 MiB per user; only the owning account can retrieve them. Inference accepts at most 10 attachments and 4 MiB of attachment data per conversation. External image URLs are not fetched by the server. Users can clear unused uploads, while referenced uploads are protected. Referenced files remain after chat deletion and require an operator-managed retention policy.

Owners can publish or unpublish plain-text announcements and independently pause registration or chat generation. Changes apply on the next request without deleting data. Missing system settings fail closed. CAPTCHA and administrator MFA cannot be disabled through the console.
